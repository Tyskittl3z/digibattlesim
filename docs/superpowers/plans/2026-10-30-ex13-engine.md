# EX13 Engine Implementation Plan

> **For agentic workers:** use superpowers:executing-plans inline. The user directed execution; do not request another permission checkpoint.

**Goal:** Make imported matchup identity and mechanic support explicit without reusing old deck-specific knowledge.

**Architecture:** Immutable per-matchup definitions feed a generic physical-state and mechanic dispatcher. Historical loaded-pair modules remain reproducible. Official evidence and independent reviews are distinct from software tests.

**Tech Stack:** Python 3.11+, standard library, unittest.

**Spec:** docs/superpowers/specs/2026-10-30-ex13-engine-design.md

## Global Constraints

- No deck changes/advice, invented outcomes, or auto-generated favorable reviews.
- No universal card support; only the selected imported cards and encountered mechanics.
- No APP/catalog/import edits, or reuse of old matchup pilots/roadmaps/results.
- Unsupported effects halt before mutation; targeted scenarios count as zero full matches.

## Review Focus

- Composition changes, including eggs and card quantities, must invalidate context.
- Caller mutation must not change previously created context or evidence.
- Wrong-seat, out-of-zone, duplicate-copy and after-terminal actions must fail safely.
- Exact effect text and official source bytes must bind pack dispatch.
- Provisional implementations must never produce judge-certified readiness.
